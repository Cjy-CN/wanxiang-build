# 万象棋阵容研究

目标是发现比现有推荐更好的搭配，并说明改进在什么条件下成立。把官方与热门阵容当作比较对象，不把热度、作者身份、推荐分或“999”“无限”等标题当作强度证据。没有支持全面胜出的证据时，交付有明确优势与失败条件的候选，而不强行宣布超过官方。

默认交付是**按回合展开的构筑决策树**：随实际来牌进入不同体系，早期可换整队，后期逐步收敛。同步提出获胜方式和成长方式，追踪资源经主C、保护者或副C转成属性、技能、可输出窗口及关键击杀的路径。等级总量是资源指标，不能先按总级或增级速度淘汰集中资源的候选，也不能预设单核优于多核。成长必须足以支持当局获胜窗口，易获取、低阶或能站满人口都不能替代这一论证。

由 agent 阅读原文、解释触发链、提出与反驳构筑、决定评分。脚本只辅助检索和复核算术；不必调用脚本即可完成分析。不以预设英雄强度表、关键词连线数量、穷举排名、自动加权器或简化战斗模拟贯穿流程。避免写一个只能从固定候选库挑选阵容的推荐器。

## 先建立本次问题

区分用户要的是从零构筑、现有阵容优化、用户提供记录的路径审计，还是当前回合决策。优先使用已给的本局禁用阵营、棋手、回合、血量、能量、场上/手牌、英雄真实等级与觉醒进度、装备、天赋、商店和对手信息。路径审计只能基于用户提供的逐回合状态、操作或战斗记录；本skill不读取游戏录像/replay，也不能仅凭终局阵容反推缺失的商店和战斗事件。未提供实战局面时，按本地资料的条件性理论研究推进；不编造开局、装备掉落或环境胜率。只问会改变推荐的关键缺项，其余明确假设。

每局开始系统随机禁用一个阵营的英雄，先排除本局被禁英雄。禁用未知时按受影响阵营列适用与换路条件；减少不可替代核心对多个阵营的依赖，不能默认全库同局可用。禁用已确定后不再假设对局中会继续随机禁用。详见规则§3.5.2与 [推理与构筑方法](references/reasoning.md)。

本skill位于项目的 `.agents/skills/wanxiang-build/`。先读 [资料与规则边界](references/sources.md)，再读取本skill内 [规则原文](data/documents/王者万象棋规则说明.md) 和 [补充说明](data/documents/补充说明.md)。卡牌等完整原文保存在 `data/documents/`，参考阵容原文保存在 `data/references/`；本层 `references/` 是分析方法。按需查询记录的全部描述、关键词、觉醒卡、技能和预览卡牌。使用名称加类型/ID定位，区分英雄瑶与棋手瑶妹、英雄马可波罗与棋手马可、两种镜和弈星。`source_config.json` 的 `data_root` 默认值为 `data`，相对本SKILL.md所在目录解析，与启动时工作目录无关；每次实际使用重新核对原文件，示例不是缓存的现行规则。

用户已补充成长模板、10/40/100级技能强化、召唤物成长和抗性模型。分析输出、生存或等级收益时读 [数值计算与新增规则](references/combat-math.md)，再查对应原文；不再将这些资料笼统列为缺失。阿科米亚核心默认按场上日落海人数均分临时等级，**不触发司空震等临时等级连锁**；竞拍分红按存活人数和系统排名查表，不把掉血本身等同于分红增加。

商店按用户2026-09-15补充处理：**升阶的新卡池下回合生效**，从品阶≤生效阶数的联合卡池抽4张；本回合手刷/补槽不提前解锁。按规则§6.1.1分开当前棋手阶数与商店生效阶数，概率由合格卡池及明确抽样假设推导，不再把独立品阶概率表当作必需缺项。

## 从获胜路径和成长引擎构建决策树

1. **同时提出获胜路径与成长引擎。** 从本局卡文和棋手技能寻找等级/资源生产、定向分配、重放与放大接口，说明谁承接资源、靠何种伤害或控制处理哪些目标、谁保证其出手。读 [成长与资源分配](references/growth.md) 和 [战斗转化评估](references/combat-evaluation.md)，对比集中、双核或分布式的可行路径；既不能只凭总增级快推荐，也不能把总增级较慢自动判为过渡。棋手已锁定时所有转型继承该棋手。
2. **还原成长并验证战斗兑现。** 对核心记录“来源 → 事件 → 合法目标 → 收益次数与类型 → 上限/持续时间 → 成本”，分开永久等级、临时等级、核心池与转移。按 [推理与构筑方法](references/reasoning.md) 核查事件与循环，从实际出牌推导等级分布。再按战斗转化评估核算属性/技能门槛、目标访问、主C输出窗口和双方关键减员后的变化；不以开战等级、全队DPS或首杀单项替代胜负分析。
3. **设计路线分叉。** 结合已知禁用、来牌和已投入资源，先选不同成长机制的候选。对≥4阶主C、≥3阶构筑牌的缺失，按 [关键牌缺失与备选](references/reasoning.md#关键牌缺失与备选) 检查何时换整套发动机、主C及购买目标，何时保留核心只换组件。早期备选不能全是原阵容补挂件；跨路线要给具体承接名单和新成长方式。不同分支的英雄不等于同局都要买。
4. **量化竞争用途，再逐回合决定动作。** 必须读 [觉醒、过牌与升阶的机会成本](references/investment.md)。从同一状态并行推导先觉醒、先升阶和有效买牌的后续路径，计入剩余觉醒费用、搜索费、门槛延迟、少看的高阶卡槽、晚入场/晚生效、天赋与人口收益。预算可支付不等于投资最优，完成体每轮增级也不能证明应当提前付9点。对R1、R2及后续节点给互斥条件下的唯一首选，不能让读者自行在觉醒和升阶之间选择。棋手等级是动作结果，不是时间轴；逐笔能量与抽槽核算留在内部。
5. **按路径比较再推荐。** 同回合、同起点、同禁用和同获取机会对照，允许双方形成不同等级与不同中间阵容。检查核心未到、已到但成长慢、转型后重建、晚期无法回本，以及相关战斗克制。将低阶保血盘明确标为过渡，并给退出回合和成长出口；没有可执行出口就不作默认完整路线。保留参考原版与可合理转型的基线，不通过冻结基线运营制造优势。

研究复杂联动或需要启发时，读 [机制案例与自检任务](references/cases.md)。先独立推导再看案例，避免把示例当作固定推荐库。

含经济/检索功能位的路线，从入场时就按 [阶段价值与退出](references/investment.md#42-经济检索功能位的阶段价值与退出) 规划停投、留用和换位。随基础收入、剩余目标和对局窗口更新其边际价值；不能用历史产出或高等级掩盖后期占位损失，也不能因收入占比下降就一律淘汰。

候选阵容按 [候选发现、扩展与淘汰](references/reasoning.md#候选发现扩展与淘汰) 从机制关系提出，关键词仅定位原文；必须针对成长与战斗缺口检查未命中的组件，不能把第一次搜索结果当作封闭候选库。涉及效果牌选择、合成锦囊或相关升阶收益时，执行 [效果牌与构筑联动评估](references/investment.md#41-效果牌与构筑联动的评估路径)：以当前阵容、手牌及后续运营的增量价值比较三选一，允许新牌改变原计划，禁止用牌的品阶或固定单卡分替代联动价值。具体评估由运行时agent完成，脚本仅辅助检索与算术。

## 量化与可信度

需要打分时读 [评分规则](references/scoring.md)。先给可核算的资源/触发指标，再由 agent 按锚点评分；每项分数关联证据、假设与反证。默认报告 100 分的理论决策评分及情景区间，不称为胜率、吃鸡率、实测排名或统计置信区间。当前战力与未来潜力分开看，不能把未来生产收益再算作当前输出。

先检验合法运营路径、资源到战斗的转化及机会成本，再加权：无法及时形成有效输出/控制或维持其必要窗口的路线，不能靠总等级、未来成长或易成型分抬成默认推荐；总级较低但有可核对战斗优势的路线不据此淘汰。未来成长必须对应尚能改善的战斗指标。分数对应具体回合与分支，不给整张树编无概率依据的平均分。静态同等级快照仅解释局部机制；关键概率缺失时给翻转阈值与明确临时动作，区分模型内最优、稳健首选与待证执行规则。

合法性失败的方案不参与推荐排名；缺规则造成的条件合法与明确非法不同。影响胜负的核心机制未明时仍可分析已知部分，但不报无条件精确总分。区间重叠或改权重就翻转时，不制造确定名次。机制证据强度与经验校准程度分别报告。

关键高阶牌缺失后没有可执行转型路径的方案不能作为默认通用攻略；拿到关键件后的条件分支仍可研究。鲁棒性要求来牌不符时能换路，新路线能兑现战斗作用并有与剩余局数匹配的成长；不是保留七个低阶单位就算合格。成型效率与缺件转型评分必须有路径依据，不以简单按阵营数扣分替代检查。

可选工具（`<skill>` 指本文件所在目录）：

```text
python -X utf8 <skill>/scripts/lookup.py inventory
python -X utf8 <skill>/scripts/lookup.py query --kind hero --name 朵莉亚
python -X utf8 <skill>/scripts/lookup.py query --kind equipment --contains 普通
python -X utf8 <skill>/scripts/lookup.py query --kind build --id 2
python -X utf8 <skill>/scripts/score.py <评分账本.json>
```

`lookup.py --root <外部资料根目录> ...` 可显式覆盖默认资料目录，该目录须含 `documents/` 与阵容 `references/`。普通调用不需要传根目录，也不依赖项目根目录或个人skill目录下的副本。检索结果含来源及定位；子卡命中时返回完整父记录。`score.py` 仅对 agent 已判断的各维度数值做校验、汇总和同情景差分，不判断阵容或证据正确性。脚本不可用时，直接读取 JSON、手算即可。

## 交付

报告先交付实操，再展开分析，按 [报告组织](references/report-format.md) 输出：

1. 开头简述棋手、禁用与适用局面，立即展示以回合为时间轴的分支流程图；边标明可观察的来牌/战力条件，节点标明购买、升本、追觉醒或转型动作。当前回合求助先显示本回合及后续分支。
2. 用逐回合操作表补全图中文字，写出各分支的买牌顺序、同名牌取舍、升级/停留、刷新/停搜、转型名单，以及装备/站位。早期有整体重构，后期有收敛；不能只给单一终局名单和一张换卡表。
3. 后置各路线等级增长与加速点、机制来源、战斗兑现、同条件对照、分支评分、失败情景与待验证项。累计能量、费用算式及逐笔预算留在内部校核；报告只呈现经核算能执行的动作，用户另问费用时再展开。未经过实战校准就明确标为理论结果。

简短请求按需压缩；全面研究保存本地 Markdown 报告与必要的评分账本。不要为了满足模板补编不存在的信息。更新原始规则或采集外部版本必须有本次任务依据；不把外部现行数据静默混入本地快照。
