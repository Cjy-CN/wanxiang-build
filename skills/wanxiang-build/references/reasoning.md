# 从机制到可执行阵容

## 把输入变成状态，而非英雄名单

记录资料版本、目标（吃分/争第一/保命/克制某人）、本局禁用阵营、棋手与能力阶段、回合、血量、可用能量、已付升级费用、人口上限、装备与天赋获取状态、对手已占关键牌。英雄分别记录品阶、真实等级、临时等级、觉醒进度、装备与位置。未知项保持未知。

“同一批英雄”在第6回合与第16回合、单张与觉醒、无保护与有免控时是不同方案。做纸面完成体比较要明确那只是条件快照，不能据此断言整条运营路线更强。

## 先处理开局禁用与阵营依赖

每局开始随机禁用一个阵营，按规则§3.5.2执行。区分两种研究口径：

- **已知禁用的本局决策：** 从主方案、过渡牌、备选牌和引擎生成目标中排除被禁英雄。不能靠多刷补救禁用，也不默认复制/发现可绕过禁用。只有已有明确例外来源才另列条件分支；不再增加“剩余阵营之后也可能被禁”的风险。
- **禁用未知的通用攻略：** 按阵营列出不可替代核心、可替换辅助、该阵营被禁后的替代路线或本局不选此构筑。可以设计多个互斥开局分支，不要求一张固定名单适合所有禁用。每个分支只假设一个阵营被禁，不将所有禁用同时叠加。

分别记录“固定名单涉及的阵营数”和“获胜/启动方式不可缺少的阵营集合”。额外外援可替换，与新增一条不可替代依赖不同。优先考虑少量阵营能运作的骨架，再评估跨阵营外援的净收益；不设无依据的最多两阵营等硬限制，也不因单阵营就认定鲁棒。若核心所在阵营被禁，单阵营构筑同样必须换路。

禁用概率未知时，给逐阵营的适用表和断链点，不把阵营数除以总阵营数称为实际失效概率。生成/发现类牌若涉及被禁目标，核对可用候选集合；无抽取规则时不编造禁用后概率提升。

## 人工事件账本

为决定胜负的组件填写即可，不必全库机械建图：

| 字段 | 应回答的问题 |
|---|---|
| 定位 | 类型、ID、字段、具体句子是什么？ |
| 生产者 | 谁真正发出事件？关键词解释还是主动能力？ |
| 事件 | 买牌、使用英雄牌、合成、登场、整备、开团、施法、耗蓝、破盾、阵亡、牺牲、出售/退场分别是哪一个？ |
| 接收者 | 英雄/单位/召唤物，阵营，品阶，自身/其他，装备最多/最近/等级最高，是否必须存活在场？ |
| 产出 | 永久级、临时级、生命上限、法力、装备、卡牌、能量、棋手生命，分别记账 |
| 计数 | 每次/每N次/每回合首次/间隔秒数/累计到上限/仅本回合？ |
| 成本 | 人口、卡张、能量、失去的旧等级、装备槽、血量、到达该阶段的时间 |
| 冲突 | 谁稀释随机目标、抢装备最多、夺走等级、吸收召唤物、摧毁图腾或提前杀死生产者？ |

分析一个事件的完整传播，再分析下一事件。例如：

`使用露娜牌 → 露娜登场 → 触发曹操整备 → 触发甄姬登场 → 获得一张牌`。

这条链里“获得牌”还没有“使用牌”。曹操重放登场也不是使用三分英雄牌，因此不能自动触发蔡文姬的使用监听。小乔响应登场，朵莉亚响应整备；“施放新月突击”不会因此再发生露娜登场。装备魔律之刃重施战斗技能也不重复英雄牌效果。

### 事件时序

先分回合开始、备战操作、战斗开始、战斗中、战斗结算与下回合。相同阶段存在读写依赖时，写两种顺序。例如瑶先分享装备再云中君计算数量，或反向执行，可能收益不同；未实测顺序不把较强顺序放进保证收益。写“每次触发”的监听与“触发2次”的事件粒度：觉醒狂铁是两个+2事件，觉醒海诺是每次核心加级额外+2，不能粗算成一次+4再加一次。

加法增益不自带递归资格。海诺额外+级、姜导封神一瞬等自身增益，未有明确规则不可再次触发自己；不把图上的环当成游戏允许的无穷递归。

用户已明确排除阿科米亚核心分配产生的临时等级连锁：记录其来源为核心分配，不触发司空震等监听。计算等级的战斗收益时结合combat-math.md的成长模板与技能节点，不能仍只读英雄JSON的基础技能。

### 随机与人口

先列合法候选集合；把对目标人数不足、可否重复和抽样权重的假设写出来。只有确定均匀无放回时，才用 `k/n` 算某英雄被选中的概率。确定性范围经常已足够筛选，没必要伪造概率。

例：觉醒裴擒虎从其他英雄随机取等级。其他英雄真实等级假设为 `[100,20,20]`，且读取真实等级并均匀，则临时等级期望约46.7。多上一个1级挂件变成 `[100,20,20,1]`，约35.3，不能说加人口必然增强。还要计新英雄战力、增益、存活伤害，以及临时等级读取语义本身的不确定性。

## 发现比基线更好的组合

### A类标签入口与棋手缺陷匹配

从零构筑且棋手未锁定时，先读 [初始构筑入口与棋手增益匹配](initial-build-player-fit.md)。用构筑研究对象核验报告的A类标签做单标签第一层召回；直接命中英雄数≥4的是母集候选，≤3的是按缺陷调用的组件/外挂入口。先读母集原文并建立不依赖棋手额外收益的初始基线，再分别记录机制、战斗、资源、时序和风险缺陷。棋手选择放在基线之后：按缺陷匹配其真实技能、秘技、专属，比较触发条件、到账阶段、成本、冲突和净收益；不能用棋手牌源掩盖母集没有战斗兑现，也不能把棋手专属机制当通用补件。只有明确缺口后才接入破盾、普攻、控制、复生、出售、夺取等组件标签，组件解决不了缺口才继续沿效果标签扩层。

先从全库描述找到收益接口，再按禁用筛选可用组件；未知禁用时保留条件分支。可检索：`每当你的英雄`、`你的单位`、`所有英雄`、`临时等级`、`整备`、`开团`、`首件普通装备`、`其他不同阵营`。这些词用于找候选，不用于自动判定兼容，也不作为鼓励堆叠阵营的指标。

### 候选发现、扩展与淘汰

构筑由 agent 在运行时提出和反驳。关键词搜索是快速定位原文的工具，**命中结果不能成为封闭候选库**；同词不证明能触发，未命中也不证明无协同。已有实战局面可围绕当前缺口缩小范围；从零研究时先浏览本局合法英雄和棋手的主要效果，按机制而非词频整理可能的成长入口，不一开始就固定一个阵营/关键词。

- **提出不同机制的骨架。** 从等级/资源生产、触发次数或目标数放大、重放/复制、转移/分配等关系中找能实际启动的组合。按资料支持选择不同增长方式，不强凑固定候选数；每个骨架先说明启动条件、成长接收者和战斗获胜方式。完成初始基线和缺陷账本后，再把棋手作为补缺候选比较；棋手已锁定时则继承其约束。
- **沿供需关系扩展。** 对监听器反查谁产生合法事件，对生产者查谁能放大或兑现产出，必要时经过效果牌、装备、天赋或召唤物连接中间环节。完整读取命中牌的描述、觉醒卡和关联子卡，明确“相同关键词”与“符合触发资格”的区别。条件性天赋/稀有装备只生成条件分支，不作为默认已拥有资源。
- **从缺口反查非关键词组件。** 对增长骨架检查前排存活、输出、启动速度、资源和目标分配；主动回到候选库之外查能补这些缺口的合法牌。保护、控制、攻速、回蓝或定向分配可能不带引擎关键词，却能增加实际触发次数或让成长兑现。也检查替代整套引擎的路线，避免只围绕最早发现的骨架补挂件。
- **从获胜手段反查资源路径。** 对可能作为主C或多核的英雄，先查成长模板、技能节点、伤害类型和目标访问，再反查谁能送来其需要的等级、装备、保护与出手时间，与从生产引擎出发的候选共同比较。按 [战斗评估](combat-evaluation.md) 检查集中/分散的边际收益；不能先用总增级排序剪掉低总量但能先处理关键目标的骨架，也不能预设主C必须是高阶射手。
- **以完整路径淘汰。** 先核对事件合法性、成型前后成长和生存，再按逐回合预算与投资比较评估启动、觉醒、升阶和缺件转型。用替换/移除组件检查其净作用，不能按连线数、阵营数量、品阶或终局总分先裁掉候选。只有无合法路径、被可执行方案支配、已证明无法及时兑现等原因才淘汰；不确定项保留条件，不伪装成已排除。
- **保留选择依据。** 内部简记主要候选的机制、保留/淘汰理由，以及针对关键缺口额外查过哪些非关键词组件。继续检索不能解决当前关键不确定性、可用机制与竞争路径已有依据时，交付有边界的首选；不声称关键词检索或有限候选比较已经穷举全库最优。

效果牌也会反过来改变骨架、主C和升级顺序；按 [效果牌与构筑联动评估](investment.md#41-效果牌与构筑联动的评估路径) 处理，不能在阵容确定后才给锦囊附加一个固定分。

值得探索的改变：

- **提高有效事件密度：** 同一人口位同时生产原生收益与监听收益；但多一个随机目标可能稀释关键触发。
- **换收益接收者：** 把等级集中给能将其转成攻速、法力或生存的英雄，而非只抬高全队总级。
- **补齐收益兑现：** 有成长却无输出/前排时，换掉一个晚期生产位引入控制、抗性、对后排或第二伤害类型。
- **提前启动：** 低阶替代高阶必备件，或只觉醒监听器而非全员觉醒；比较省出的能量和卡池压力。
- **改变时机：** 生产位的下一轮收益抵不过马上被淘汰时，将其换成战斗位；说明丢掉的成长与已沉淀等级。
- **拒绝负协同：** 刘邦摧毁图腾会让敖隐失去后续按图腾获得的收益；大司命吸收低阶召唤物会改变少司缘的攻击次数来源；机器头固定攻速与高速射手的收益需重新判断。

全新构筑研究维护不同成长机制的路线，按来牌连接为决策树。联合 [成长与分配](growth.md) 和 [战斗评估](combat-evaluation.md) 检查启动、资源去向与获胜方式，并给经济/检索位规划退出。保留参考原版和可合理运营的基线。单卡/成组消融可用于解释具体放大点，但不能代替早期整套换路；树不是多个互不相干的终局名单。

不把本技能案例固化成推荐表。数据更新、棋手改变、环境未知时，从当前原文重新构筑。

## 关键牌缺失与备选

对每张**品阶≥4主C、品阶≥3构筑牌**（含边界），列出它缺失时失效的整条增长路径。构筑牌包括生产、重放、监听、资源转换和关键保护。低阶核心也可能缺失；已持单张与尚缺觉醒进度分开检查。这是定位分叉触发点，不是强制给每张牌找一个同位置替身。

默认随回合推进减少转型幅度，具体由已积累等级、已投入卡张、装备绑定、棋手适配与剩余生存窗口决定：

- **早期：** 来牌不支持原引擎、另一引擎已有可用组件时，允许更换主C、生产与放大组件、阵营方向及后续采购目标，甚至换整队。先保留尚未承诺的购牌机会，不为维持原名单继续买没有回本空间的重复牌。
- **中期：** 比较保留能继承的高等级单位/生产资产后换一组组件，或彻底换发动机。计算停产与重建时间；一次性换不齐时给出逐回合过渡顺序，不能先卖光再等新牌。
- **后期：** 已有高速引擎和等级积累时主要强化、补觉醒、调整战斗位或少量替换。原核心晚来但低等级、装备无法接续或来不及回本时不转回原路线。整队换路只有在已持新体系、可执行且净收益足够时作为明确例外；不是绝对禁止。

早/中/后期必须落到报告的具体回合。阶段名只帮助分析，不能替代R几的动作。分叉条件使用当时已经看得到的卡、张数、成长状态与战况，不用未来会抽到的牌替过去作决定。所有分支继承已选棋手；开局棋手选择是单独前置决策，不允许对局中免费更换。

每条转型边说明：

| 内容 | 应当写清的决策 |
|---|---|
| 当前节点 | R几、当前阵容/等级资产、核心单张与觉醒进度、已投入不可回收资源 |
| 触发条件 | 原引擎何时仍未齐/速度落后；已到哪组替代引擎组件；两套都到时选哪套、都没到时怎样保血并何时重判 |
| 换路动作 | 保留谁、先买谁、何时卖谁、停止追哪些同名牌；换后的完整中间阵容与下一回合采购目标 |
| 新增长方式 | 新路线靠什么放大队伍等级、何时启动；不能沿用已移除原组件的产出 |
| 回收与损失 | 等级留存与损失、装备可否转移、出售回收、重建开销、停产回合；预算细节内部核对 |
| 后续去向 | 成功后收敛到哪个节点；替代牌也未到或新路线无法及时兑现战斗作用时的实际出口，不能无期限“再等等” |

替代方向可以跨出原阵营和原获胜方式，前提是本局未禁、棋手与资源可承接，且新引擎本身值得运营。不能只用“已有/低阶牌顶上”证明鲁棒；保血盘须标明临时用途、下一次重判的具体回合和增长出口。另一张未到高阶牌不是唯一出口。

至少分析未到、晚到单张、无法觉醒、相关关键件共同缺失，以及齐件但引擎依然慢。早期有可行不同引擎时必须给真正换体系的分支；若因当前已锁状态无法大转，则说明限制并只给可执行分支，不能为了图好看捏造路线。

来自不同前史的路径只有在核心、保留等级、棋手、装备与下一步购买决策相容时才汇合。可以共享后续说明，但不能重置到相同等级/相同剩余能量。逐路径维护状态，不能把多条互斥路线的收益同时算在一个队里。

## 循环与上限检验

每个“倒转/永动/无限复活”假设都要回答：

1. 启动事件需要什么牌、能量、人口与状态？
2. 一次循环实际退回什么资源，生成牌类型、阶数与目标概率是什么？
3. 返回的资源是否足以再执行？还受手牌、卡池、次数、操作时间、临时牌到期和999级上限约束吗？
4. 含随机分支时，不利分支是否立即断链？生成牌是否计购买、使用或合成？
5. 就算循环可重复，是否转成战斗优势，是否来得及完成？

仅在独立同分布、固定延续概率p且每步成本c的玩具模型下，p<1时启动后包含首步的期望执行次数为1/(1−p)，期望成本为c/(1−p)。真实牌池与资源变化时不套此式；p未知只给情景。不把期望延续称为保证无限。

## 成型与运营

以回合为索引，在内部为每条路径维护收支恒等式：

`期末能量 = 期初 + 固定收入 + 已确认返利/出售/分红 − 买英雄 − 付费秘技/卡牌 − 升级 − 手刷 − 竞拍 − 棋手技能等费用`。

6/5/4/3人分红比例已知，按规则§7.3的存活人数/系统排名查表；池额未知时写P×比例，不用虚构分红补平负账。2/1人、并列与取整规则未给时保留未知。普通效果锦囊及其生成的普通效果牌不消耗能量；明确收费秘技另记使用费，例如「如梦似幻」6能量，已拿到牌不能免除费用。具体卡文、同槽是否出现相同牌和同回合使用次数仍需核对。基础合成额外成长未知不影响“花了多少能量”的校验。资源下界可证明不可能，却不能证明抽牌能实现。

同名英雄由0进度觉醒一般再需3张，商店额外9能量；全新英雄连首次共12能量。弦音/妙音/复制/棋手能力按真实来源替换，不能既减张数又再计一次免费收益。部署扩编有条件成本；少人口应量化聚焦收益与少人的损失。

核对各回合开始时现金与每一步支出，而不是只检查“到R12总收入够”。新阶数卡池在升阶的下一个回合才生效；本回合手刷/购买补槽仍按回合开始时的商店阶数，不能通过付费绕过。人口、天赋、回合开始触发与买入当轮能否生效分别按各自规则处理。未来分红/收入不能支付本轮动作；卖掉旧英雄才能腾出的资源也不能在出售前重复使用。某条分支付不起，就推迟到明确下一回合或改变买牌/升本顺序。

按 [投资比较](investment.md) 从同一状态量化“买新核心、买已有同名牌、升棋手、刷新或停搜”的机会成本；下面的问题用于建立竞争动作，不能代替正式比较：

- 买同名牌：写清距第4张还差多少、这张是否改变速度、是否会在转型时浪费；不默认见到就买，也不一律只用单张。先完成放大器觉醒必须胜过同资源的升阶/有效买牌路径，不能由放大器身份直接决定优先级。
- 升棋手：是否解锁关键放大器、人口或棋手能力，是否比当轮完成觉醒更早加速；新增品阶机会不是保证拿到牌。不加人口的升级也可能有发动机价值，必须具体比较。
- 刷新/停搜：目标是完成可回本的增长入口；同名牌与新引擎争用预算时给取舍。仍未到时在明确回合进入替代分支，不无限延后。

最终报告给“R几在什么明确条件下首选什么、放弃哪个竞争动作、R几再检查”，每片叶子只留一个动作；不得写“两个选项都行”。初始商店未知时采用合法的条件分支；缺抽卡概率时给翻转边界与临时执行规则，不把未知变成确定最优。用户没有要费用讲解时，期末余额、累计收入和推导留在内部校核。

每个回合还需检查：

- 有核心监听器、有启动生产者、有能撑到兑现的战力，才承诺该路线。
- 将升本、刷新、补当前战力放进同一能量预算；血量能否承受下一次失败用当回合扣血范围核算。
- 基础收益已封顶、来不及回本、同行使商店路线不足或关键机制未证时停止追逐该上限。
- 装备最多的目标用装备数量严格领先控制；最近目标尽量唯一，防并列随机。没有几何规则时描述相对站位和实战检查方法。

## 反证与实际观察

对推荐者使用和基线同样严格的标准。同步检验齐件后的资源分配、有效成长和战斗路径，再检验关键牌未到、晚到、共同缺失、提前大转与晚期拒绝大转；禁用未知时逐个核心阵营被禁检查换路。按 [战斗评估](combat-evaluation.md) 比较先处理关键目标、主C可用输出时间和减员后的状态；同时检查集中资源被针对与分散资源并行输出的反例。其他压力场景选择与胜利条件相关的几类：早期压血、后排突击、开局控制、控制免疫但不免压制、物理防御/反普攻、持续治疗/护盾、针对最高等级、核心牌被争抢。

每次写出“哪条链断了 → 谁先失去作用 → 可用什么资源补救 → 替换损失”。输出具体失败条件比再加一条泛泛优点有价值。

没有战斗引擎时做原文反证、成本检查和事件手算，不写伪实测。实际验证先测最影响名次的未知机制，再在相近回合/资源、相同对手配置下对照；记录版本、阵容、等级、装备、天赋、站位、目标选择、触发次数、英雄存活和棋手扣血。少量观察只报告样本，不称环境胜率；上分效果需完整对局及争抢、运营影响，不能靠单场切磋替代。
