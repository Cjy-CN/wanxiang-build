# 初始构筑入口与棋手增益匹配

本文件将已核验的21个A类标签接入阵容研究流程，完整入口与命中统计见下文路由表，并整理当前本地资料中的19名棋手（阿离9月17日10点上线，9月18日维护）。它解决的是“从哪个机制入口建立初始构筑、初始构筑出现什么缺陷、选哪个棋手补缺口”的顺序问题，不是阵容强度排名，也不是把每个标签直接变成一套完整阵容。原始实验报告不随开源包分发，使用本文件不依赖该报告。

当前 `data/documents/` 五份原始卡库与正式精简标签均为530条父记录：2026-09-17用户核验的529条加本次新增阿离（官方ID20，用户确认）。阿离标签为「护盾、位移、击杀、升级」，均不是A类词，因此不改变下表A类直接命中数、英雄母集数量及21个入口的路由。技能/普攻等分支按本文件棋手表与原文补查。每次实际研究仍要回读当前英雄、效果牌、天赋、装备和棋手原文；本文件的表格是路由索引，原文才是触发资格、时序、数值和限制的依据。

## 一、A类标签如何进入初始构筑

### 1. 母集与外挂的操作定义

21个 A 类标签全部保留为第一层检索入口。为避免低英雄命中标签把阵容母集拉得过窄，当前采用一个可复核的路由阈值：**直接命中的英雄数 ≥4，标为“母集候选”；直接命中的英雄数 ≤3，标为“组件/外挂入口”。** 这是检索角色的默认划分，不是强弱判断；原文若显示某个组件能独立形成事件链，可在后续审计中升格。

“直接命中英雄数”只统计精简标签中类型为英雄的父记录，不统计天赋、效果牌、装备或棋手。英雄数少也不能删掉标签：组件仍可以在某个母集暴露出缺口时被定向加入。英雄数多也不证明一层已经足够成阵，仍要验证生产者、接收者、战斗兑现和获取可行性。

因此，默认的**母集候选**是15项：登场、整备、开团、牺牲、召唤、图腾、核心、古币、战术牌、效果牌、临时等级、闪现、合成、装备、技能；**组件/外挂入口**是6项：破盾、普攻、控制、复生、出售、夺取。组件不是低价值卡包，而是“只有在某个母集出现相应缺陷时才优先接入”的检索路由。

### 3. 初始构筑的固定顺序

1. **选一个A类标签做第一层。** 召回该标签命中的英雄、天赋、效果牌、装备和棋手，但先把英雄母集与跨卡类配件分开。阵营、阶数和装备分类只作合法性、卡池和获取阶段筛选。
2. **在母集英雄中选机制角色。** 阅读描述、觉醒、关键词解释、技能和预览子卡，标出事件生产者、监听者、收益承接者、前排/保护和输出/控制位。不要按命中数量取前七张，也不要把全标签相交最多的卡自动当核心。
3. **先写不依赖特定棋手的初始基线。** 基线至少要说明：启动事件、成长接收者、战斗获胜手段、保护/目标访问、当前缺口。棋手可以影响获取速度，但不能被用来假定原本不存在的触发资格。
4. **建立缺陷账本。** 分开记录：机制缺口（没有生产者/监听者/合法目标）、战斗缺口（承伤、输出、控制、后排访问）、资源缺口（能量、牌源、刷新、觉醒/升阶机会成本）、时序缺口（来不及在战斗窗口生效）和风险（随机目标、禁用、冲突、关键牌依赖）。
5. **按缺陷匹配棋手。** 先查本文件的增益类型，选择能直接改善当前缺陷的棋手；同时记录触发条件、作用阶段、成本/机会成本、与初始引擎的冲突，以及补短板后仍剩的缺口。至少保留一个不换棋手的基线和一个候选替代，比较净收益。
6. **按缺口调用组件标签。** 例如召唤母集缺少攻击次数兑现时再查“普攻”；技能母集缺少稳定施控时再查“控制”；牺牲母集缺少可重复再出手时再查“复生”。组件加入后重新检查人口、装备、目标和时序，而不是把组件命中卡全部并入母集。
7. **组件仍不足才扩层。** 只有原文明确暴露缺口，才沿缺口选择下一个效果标签；达到机制可运行、战斗能兑现且获取路径可行时停止默认扩层，进入搭配、棋手比较和反证。

若棋手已由用户锁定，则顺序改为“棋手约束 → A类母集筛选 → 缺陷分析 → 组件扩展”；不能在锁定棋手后再假设可以自由更换。若起始标签本身是组件类，允许直接查询，但默认把它接到最接近的母集，而不是强行用它组成七人母集。

## 二、棋手增益类型与适配缺陷

### 1. 选择原则

棋手的“增益类型”按其真实能力的主要作用归类，不按棋手名称或关联卡牌标签归类。一个棋手可以有多个类型，但一次构筑要指定**主作用**和**副作用**：

- **牌源/检索**：增加指定或随机英雄、效果牌、复制牌，解决关键件难找；生成牌不等于已经使用，仍需预算和人口。
- **事件复用**：重复登场、整备、效果牌或上一回合出牌，解决事件密度不足；必须核对重放是否重新计入目标事件。
- **等级/属性放大**：把出牌、回合、胜负或随机助力转成永久/临时等级和属性；必须区分真实、临时、转化和上限。
- **经济/刷新/升级**：提供能量、经验、刷新、折扣或商店改造；只能改善获取和节奏，不能替代战斗兑现。
- **战斗输出/目标访问**：复制敌方单位、棋手炮击、宝藏强化或控制；要按战斗开始、中途和结算分开。
- **保护/承伤/续航**：护盾、复生、嘲讽、吸血、免控或伤害转移；要检查是否保护到真正的收益承接者。
- **专属机制**：机关、小鹿、卦象、武器改造等，必须先锁定棋手再研究，不能当作通用外挂。

### 3. 按缺陷反查棋手

下表是筛选顺序，不是“一个缺陷固定对应一个最佳棋手”。同一缺陷至少比较一个稳定方案和一个高上限方案，并把触发成本、剩余回合和与母集的冲突写出来。

| 初始构筑缺陷 | 首查棋手 | 比较时必须问 |
|---|---|---|
| 核心牌/关键天赋难找 | 庄小鱼、嬴律、闹闹、镜、白歌、玉环 | 牌是随机还是可指定？生成后还缺多少能量、人口和使用事件？ |
| 效果牌不足或使用次数不够 | 小妲己、庄小鱼、孙小宾、嬴律、玉环 | 每回合实际能打出几张？重复是否真的再次计入目标监听？ |
| 等级增长慢、主C无法集中 | 姜导、常小娥、嬴律、昭君、玉环、阿离（需先获击杀） | 是永久、临时还是变换继承？能否赶在战斗窗口改善关键属性/技能节点？ |
| 缺经济、刷新或升级节奏 | 嬴律、明先生、庄小鱼、小妲己、马可 | 额外资源是否在需要的回合到账？是否以降低战力、购买次数或决策机会为代价？ |
| 缺保护、承伤或主C出手窗口 | 瑶妹、班叔、姜导、昭君、阿离 | 保护对象是否能覆盖真正的收益承接者？免控是否排除压制？机关/小鹿是否占用或绕开人口？ |
| 缺输出、收割或敌方后排访问 | 香香、弈星、乔汐、马可、昭君；阿离按强化与伞位条件补查 | 是持续输出、即时爆发还是临时单位？能否在主C成型前过渡并在后期退出？ |
| 事件触发密度不足 | 孙小宾、镜、玉环、小妲己；阿离（枫之洪流，仅战斗施法） | 复用的是卡牌、效果还是战斗技能？会不会与母集的随机目标、次数上限冲突？ |
| 缺控制或目标限制 | 昭君、班叔、嬴律、弈星 | 控制发生在备战、战斗开始还是战斗中？能否满足马超/控制感应等监听资格？ |
| 低阶过渡无法转为后期价值 | 马可、嬴律、姜导、玉环 | 低阶牌是否只是占人口，还是能转宝藏、等级、复制或棋手资源？退出回合是什么？ |

棋手补短板的判断结果可以是“补齐”“部分缓解”“与母集冲突”或“无效”。如果某棋手只提供经济/牌源，却无法解决母集的战斗兑现缺陷，不能因为获取顺畅就把它列为默认首选。

### 4. 阿离的具体分支与启动条件

依据9月18日维护的[公告补充](../data/documents/补充说明.md#2026-09-18-核心玩法资料更新)。阿离主技能给绑定英雄提供受伤后的护盾与转移；先评估该英雄能否活到触发、转移后能否继续接敌，再评价击杀解锁收益。不要以尚未解锁的成长证明弱核能够拿到启动击杀。

| 来源/分支 | 可补的缺陷与收益 | 核算边界 |
|---|---|---|
| 惊鸿游龙 | 绑定英雄击败3/7/11/15名敌方英雄，分阶段获得翩跹舞步并解锁特性 | 只计指定英雄击败敌方英雄；不把全队击杀、助攻或召唤物击杀默认计入。解锁顺序与强化池未明确，不预设阈值和四项特性的一一对应 |
| 蓄势 / 新生 | 蓄势每击败敌方英雄永久+1级；新生每回合+2级且转移后恢复10%最大生命 | 分开记录击杀成长、回合成长和转移治疗；新生的+2未明确永久/临时，不外推全部为永久等级 |
| 流动 / 进化 | 流动在转移后每击败3名敌方英雄增加1次转移；进化按绑定英雄本局击败敌方英雄数×4增加双攻 | 前者有转移与击杀前置，后者是本局击杀数读数；都不能用全队总击杀替代 |
| 即刻起舞·落英汲取 | 转移后按自身最大生命20%对1格内每个敌人造成法伤，按敌人数×3%最大生命治疗自身；适合缺近身范围输出/续航的承接者 | 取决于转移后的邻近敌人数；不能预设满额治疗或把基于最大生命的伤害当真伤 |
| 即刻起舞·枫之洪流 | 首次转移后3秒可无限释放技能；用于「技能」母集已有收益者的施法窗口缺口 | 不等于无限实际施法次数、无限持续时间或固定耗蓝；自然法杖等按实际法力消耗核验，不自动接入耗蓝收益 |
| 即刻起舞·翩跹馈赠 | 转移后累积15次普攻增加1次转移；用于「普攻」组件已有攻击频率的保护续接 | 只有绑定英雄的攻击计数；攻击、施法和转移的时间竞争需比较，不预设普通攻击与连续施法同时满速 |

四项特性来自击杀里程碑，各项另可挑选强化牌；「即刻起舞」按现行通用规则§2.3为棋手6级专属，三项择一，不能直接把三个专属收益同时计入。里程碑强化牌能否再选这些强化、是否重复/叠加，待具体池与规则补齐。

与牺牲阵容组合时，延后死亡可能同时延后牺牲收益；与破盾组件组合时，供盾不保证及时破盾；与闪现阵容组合时，须分别检查英雄自身闪现和枫叶舞转移，不能互代事件。纸伞放置规则未明时，只能提出条件性接敌方案，不能宣称稳定切后排。

## 三、把流程写进阵容报告

初始构筑报告至少保留以下记录，便于复核棋手是否真的补了短板：

| 记录段 | 内容 |
|---|---|
| 入口 | 起始A标签、母集/组件角色、直接命中英雄数、当前禁用与卡池生效阶数 |
| 基线 | 第一层阅读后保留的事件生产者、监听者、承接者、输出/保护位；不预设棋手额外触发 |
| 缺陷账本 | 机制、战斗、资源、时序、随机性、禁用和人口冲突；每条缺陷写影响的获胜路径 |
| 棋手候选 | 每名候选的具体技能/秘技/专属、到账阶段、补缺方式、成本、冲突和未解决问题 |
| 组件扩展 | 从缺陷反查的A类组件标签、加入理由、新增卡牌、停止扩层条件 |
| 对照结论 | 不换棋手基线、补短板方案、放大优势方案；同一获取与回合条件下比较净收益 |
| 转型出口 | 关键棋手或组件未到时，何时换母集、保留哪些等级/装备、何时退出原路线 |

推荐句式是：**“以A标签X建立母集，当前缺陷是Y；棋手Z在条件W下通过机制Q改善Y，代价是C，仍剩缺陷R，因此在同一回合/资源对照中优于或不优于基线。”**

不要写成“X标签最适合Z棋手”。标签只是第一层召回；棋手结论必须依赖该局初始构筑暴露的具体缺陷。若所有候选棋手都不能改善决定胜负的缺口，应保留原基线、扩展组件或改换母集，不强行选一个棋手。

## 四、几个边界例子

- **召唤母集 + 普攻组件：** 普攻直接命中英雄为0，但因缘图腾的原文将合计25次普攻转为全队永久等级；只有召唤物或英雄能稳定产生攻击次数时，才把它作为召唤阵容的成长外挂。不能因为“普攻”命中装备多，就把全部普攻装备当核心。
- **破盾组件 + 生命/护盾配套：** 破盾直接命中英雄2个，墨子和扁鹊分别消费破盾事件；先查御灵之纱、廉颇等实际供盾，再决定是否值得进入完整构筑。护盾被吸收、护盾被击破和护盾转生命不是同一事件。
- **登场母集 + 事件复用棋手：** 小妲己重复的是效果牌，孙小宾记录并重放英雄/效果牌；两者都可能提高事件密度，但不能直接当作“再次登场”或“再次购买”。逐事件账本确认后再给收益。
- **牺牲母集 + 瑶妹：** 瑶妹主要解决保护和额外战斗单位问题，小鹿阵亡不自动成为英雄牺牲；是否纳入取决于牺牲单位需要不需要更长输出窗口，不能只因都有“召唤/死亡”字面关系相连。
- **装备母集 + 云中君/嬴律：** 云中君是英雄标签中的装备数量成长承接者；嬴律能从经济、刷新或决策侧改善拿装备的节奏。两者比较的是“装备数量能否在本回合转为有效等级和战斗”，不是装备标签命中数。
