# 从资源分配到战斗胜负

用于选择成长引擎、主C/副C、资源接收者，以及比较觉醒、升阶、效果牌和战斗位替换。先按 [数值口径](combat-math.md) 读取成长模板、技能强化与伤害资料，再执行本节。由 agent 建立有来源的局部计算和条件推演；不要求用静态战斗模拟器代替构筑判断。

## 1. 同时提出获胜方式与成长方式

用户观察到集中资源的队伍有时能在全队总等级较低时先打掉关键单位，也见过数量不可忽略的反例。这是需要解释和检验的观察，不是“单核必胜”或固定环境胜率。此前优先扩大全队等级总量的筛选可能漏掉有更好战斗转化的构筑；不能反过来固定偏爱单核。

每个候选先回答：谁通过什么伤害、控制或消耗方式处理哪些目标，谁创造其输出窗口，增长资源如何到达这些单位。全队等级总和记录生产规模，不能替代获胜条件。主C可以是射手、法师、战士、召唤者或以生命转换伤害的坦克；单核、双核、分布式输出是资源安排的候选结果，不是预先设定的优劣排名。

资源集中与伤害集中分别检查：一个高等级主C可能伤害分散，多名英雄也可能同时攻击同一目标。低总级获胜还可能来自先手控制、技能节点、伤害类型、装备和站位，不能未经对照就归因于单核。

## 2. 建立每名关键英雄的资源转化路径

按实际运营前史记录，不能自由搬运不支持转移的等级/装备。资源分配动作必须由具体卡文、目标选择、购买、替换或站位实现；随机接收与核心均分按实际分布处理。棋手、装备、效果牌与天赋共同参与路径。

| 路径环节 | 必须解释的内容 |
|---|---|
| 资源来源与到达 | 能量、同名牌、锦囊、永久/临时等级、装备由谁提供，R几到达，代价和概率是什么 |
| 接收与门槛 | 谁得到多少，实际是否可定向，真实等级/觉醒/技能节点分别何时跨越 |
| 属性到技能 | 攻击/法攻/生命/抗性/攻速如何进入普攻、技能、召唤物或保护效果，按本地模板计算 |
| 技能到出手 | 距离、目标选择、移动、回蓝、施法、控制与存活是否允许效果发生 |
| 出手到战局 | 是否更早有效击杀关键目标、打断关键施法、延长核心输出、维持治疗/生产，或只是过量伤害与未兑现面板 |
| 后续代价 | 核心被针对后的备用输出、队友薄弱点、失去的生产速度、换牌等级损失和剩余局数 |

辅助资源不是天然低效。把等级给前排让主C多攻击几次、给辅助跨过控制/攻速节点，都可能比继续抬主C面板更赚；反之，给已足够完成任务的挂件继续增级，可能无法改变关键战斗事件。判断其边际效果，不给英雄角色预置恒定权重。

经济/检索功能位还须按 [阶段价值与退出](investment.md#42-经济检索功能位的阶段价值与退出) 评估其剩余用途和占位代价：后期累计等级很高也可能已难兑现，基础收入提高也不保证其功能失效。将保留当前战力、转移再退出或直接替换的合法路径放入比较，不能只看过去赚过多少资源。

## 3. 按属性和技能节点计算增量

用实际可执行的投资前后状态求差：`Δ属性 = 属性(L后) − 属性(L前)`，再代入该英雄的技能与目标抗性。等级线性增长不表示战力线性：攻击与攻速、生命与抗性可能相乘，技能节点有跳变；部分控制时长却不随普通等级增长。跨节点、叠加顺序和临时等级资格仍按原文核对。

以下只是局部数值校核，来源为 `data/documents/王者万象棋_英雄成长与属性值关系.md` 的普通射手/物理坦克模板、对应技能强化表和木桩抗性模型。不是一场同资源对局，也不假定玩家可免费把1级转给任意英雄。

| 校核项 | L39 → L40 | 能支持的判断 |
|---|---|---|
| 虞姬物攻 | `36+1.8×38=104.4` → `106.2` | 物攻线性增加1.8 |
| 虞姬基础攻速与普攻输出率 | `1.05→1.1`；未减伤普攻率 `109.62→116.82`，约+6.57% | 持续可攻击、无暴击/技能/装备修正时成立；她40级另有落地后+50%攻速3秒，须实际施法才能兑现，不直接并入常驻攻速 |
| 牛魔生命与物防 | `1584/22` → `1617/25` | 按单一物理伤害模型，等效生命 `2455.2→2627.625`，约+7.02%；对纯法术伤害没有这次物防增益 |
| 牛魔40级控制 | 技能新增击飞并眩晕1秒 | 能否保护主C取决于施法、命中和控制资格，不能把1秒名义控制直接算为1秒全队免费输出 |

6.57%输出与7.02%承伤不能直接比较大小来决定投谁。应检查这次变化是否减少击杀所需出手，或让前排撑过敌人爆发/己方第二次施法。少司缘40级给沿途友军攻速、张良40级削法力等也可能通过队友改变战局；不能仅凭主C系数高排除这些节点。

## 4. 从开战面板推进到关键减员

区分游戏回合R与单场战斗时间τ。每条路线使用由各自运营形成的真实状态；双方同时行动，不假定对手在计算主C输出时站着不动。按必要粒度检查接敌、第一轮普攻/技能、首次关键失能或减员、减员后到胜负/复生的阶段。

### 目标与可兑现输出

先确定攻击者可能接触谁、技能如何选目标、队友能否集火。无后排访问规则就先按其实际面对的前排算，不能把最高伤害默认打到敌方核心。范围伤害按各目标实际命中单独结算，不把不同目标承受的伤害相加用于杀死一个目标。

对目标j，检查截止τ真正能发生的攻击/技能事件，累计 `D_j(τ)=Σ d(i→j,事件)`；每个d已经按当时等级、装备、伤害类型、命中与抗性结算。移动、控制、施法停顿、换目标与过量伤害分别处理，不同时把互斥的施法和普攻算满。没有完整回蓝/时序资料时，用可证的出手次数、上下界或临界条件，不编造精确秒数或实际命中率。

`T击倒,j = inf{τ : 目标j在本阶段首次生命≤0}` 是局部时点；护盾按实际吸收事件扣除，治疗只计击倒前且未溢出的有效量。免伤、无法选中、复生与分担单独处理。仅无回复、无护盾、恒定输出且持续接触的玩具模型可用 `HP/减伤后DPS` 近似；若已用减伤后DPS，不再用等效生命重复减伤。

同时求己方主C、关键前排与保护者何时死亡或失能。核心存活时间不等于可输出时间：被压制但未死、持续找不到目标、施法前被打断都可能失去窗口。一次短控不是永久退场，必须继续跟踪控制结束后的恢复；输出达到阈值也不保证整个队伍获胜。

### 首个关键单位退场后的反馈

击倒、失能、永久退出本场战斗分别记录。识别倒下单位实际承担的输出、控制、治疗、保护或战斗中生产职能，移除它**尚未发生**的贡献，重算目标分配与下一关键事件。已经结算的开团增级/装备效果不因来源阵亡自动撤销，复生和牺牲收益也可能使早击倒反而帮助对手；不把所有减员都等价为优势。

主C更早击杀敌方关键单位，可能减少己方后续承伤并延长输出窗口，形成滚动优势；这是需要通过事件链支持的结果，不是可再额外相加的一份“滚雪球加分”。分布式输出也可能并行击杀多个目标，或在失去一人后继续工作。首个击杀后至少推进到优势被保留、被反制或仍无法判定的节点，不能用拿到首杀代替胜负证明。

### 用边界判断可信程度

对关键未知量给有依据的情景：目标访问、前排可支撑时间、施法次数、控制覆盖或恢复量。若在所有约定情景中，某路线都能在敌方关键反制前完成有效击杀，再继续验证后续战局，可称该范围内稳健；时间区间重叠则不能确定事件顺序。应写“至少需几次命中/前排需撑到哪次施法/何种站位可接触目标”，而非无依据的精确胜率。没有上下界时坦承该比较待验证，不把未知输出窗口视为0。

## 5. 比较下一笔资源的去向

从同一决策状态列出实际可执行的竞争动作：强化主C、补保护或前排节点、发展副C、扩充群体成长引擎、升阶接新组件、保留资源。相关动作才比较，不强制每个节点凑齐所有类别。每种动作保留自己的获取、觉醒、合成锦囊、天赋、卡池延迟与缺件分支。

用 [投资比较](investment.md) 推进至共同期限，输出以下变化，而非先最大化全队新增等级：

| 动作对照 | 核心战斗检查 | 长期检查 |
|---|---|---|
| 继续养主C vs 补前排/保护 | 缩短关键目标击杀所需事件，还是延长可输出窗口更能改变胜负 | 主C是否封顶、过量伤害；保护是否拖慢下一轮关键成长 |
| 单核 vs 副C/分布式 | 单核被控制、绕前排击杀、伤害类型被克制时，第二条输出路径能否继续工作 | 分资源后双方是否都错过技能/觉醒门槛、重建能否回本 |
| 战斗位 vs 成长位 | 是否需要放弃一部分生产才能活过当前回合、阻止对方引擎兑现 | 余下局数内新增成长是否能实际改变关键战斗指标 |

同一棋盘任意重排相同总等级只可用于敏感性诊断，不作为合法运营路径。若两种分配无法从同样资源机会实现，报告其成本差，不能抹平。资源集中也不等于减少人口，不能免费假定少上英雄会把其等级转给主C。

量化先保留多项结果：关键目标击杀/己方失能的事件或时间区间、实际输出窗口、减员后可用伤害源、存活英雄与棋手扣血、未来有效成长及剩余资源。具有共同效用定义和可信概率时才算期望；否则逐情景比较支配关系、翻转条件和明确临时首选。不用固定“主C等级×权重”或“集中度系数”把这些压成貌似精确的战力。

## 6. 对单核和分散方案使用同样严格的反例

从与实际对手和候选相关的行选择压力情景，同时保留能反驳推荐的一侧；这些不是已知环境分布。

| 情景 | 集中资源可能改善什么 | 集中资源可能损失什么 |
|---|---|---|
| 可访问的脆弱关键单位 | 更早击杀，阻断治疗/输出或正在工作的生产 | 若伤害打到无关前排、复生诱饵或过量溢出，面板优势可能无用 |
| 多人承受范围伤害、需多路处理 | 高生存主C可能独自扛住 | 薄弱队友同时阵亡，失去控制/供给；副C/群体生存可能更重要 |
| 定向控制、压制、切后排 | 专门保护可使核心持续工作 | 主C单点失能，全队主要伤害中断；分布式输出有冗余 |
| 高抗、反普攻或对特定伤害免疫 | 若能合法补穿透/换目标仍可集中突破 | 单一伤害通道受阻，混合伤害副C可能有更高边际价值 |
| 长战、回复、召唤与牺牲 | 爆发跨过恢复阈值可能阻止循环 | 一轮爆发未击杀后被恢复，或击杀触发复生/牺牲收益；多单位持续输出可能更优 |
| 对手尚未启动的成长引擎 | 当轮压制可减少对方兑现机会 | 若无法持续获胜或伤害不足以淘汰，对方后续成长仍可能反超 |

保护完善的单核与资源充足的多核都可能通过某些检查；不能把单核设成完美站位而让多核裸奔，或反向处理。用户描述的多数感受不能自动变成情景权重。

## 7. 输出证据与迭代验证

内部最小记录：`R/路径 → 实际资源去向 → 属性/技能增量 → 目标与可出手条件 → 双方关键事件顺序 → 减员后变化 → 未来成长与代价 → 首选及翻转条件`。实操区仍先按回合给动作，后置简洁证据。

证据分层：属性/单次伤害算术校核；有明确假设的局部战斗边界；能覆盖关键先后手的事件推演；配对实战观察。前一层不能冒充后一层。只算出更多等级或更高木桩DPS时，战斗优势仍待验证；不同角色局部指标不能直接相减。

需要实测时先测最可能翻转结论的缺项。记录双方英雄及真实/临时等级、觉醒、装备、天赋、站位、目标、前排倒下时点、核心被控/可攻击时长、首次关键击杀/复生和结果。在同一回合与相近资源机会下配对比较，仅改变待验证分配，遇到随机目标/暴击等记录重复样本及不利结果。固定对手的切磋不能代表运营成型率或环境胜率；若要推广需再覆盖相关对手与来牌路径。不得把未经运行的战斗模拟或纸面例子称为实测。
