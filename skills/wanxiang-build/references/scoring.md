# 评分：可解释的决策量表

## 分数的含义

默认是**理论决策评分**，不是经验训练出的模型，不是胜率。用于同一版本、同一资源机会、同一阶段和对手假设下比较方案。方法版本 `wxq-rubric-1`。每维0–5分，总分 `S = Σ(权重 × 维度分/5)`，默认权重合计100。用户可改目标/权重，但必须在比较前说明，并对基线和挑战者统一应用。

本次策略依据版本为 `wxq-policy-4`：按资源到战斗的转化检验路线，比较主C/保护/副C的边际投资、关键减员与后续战局；保留逐回合机会成本、锦囊联动、早转晚收敛和每节点唯一首选。算术格式仍为 `wxq-rubric-1`，8维权重不变，成长锚点改为可兑现的未来提升。旧报告须重查其决策依据，不能只改版本号复用分数；新报告说明具体回合、路径与来牌假设。

先算事实指标，再判断它对战斗的意义，最后打分。不能先想让新阵容赢几分，再倒填维度。下表的3分是中等、成立但有明显条件的设计，不是官方阵容的保底分。

| 键 / 维度 | 权重 | 0分 | 1分 | 3分 | 5分 |
|---|---:|---|---|---|---|
| damage / 战力兑现 | 20 | 无有效胜利手段 | 伤害路径易中断或明显缺转换 | 可用主C与输出窗口，有明确盲点 | 同阶段资源下可靠解决主要目标，证据支持优于备选 |
| survival / 生存与保护 | 20 | 核心无法进入输出阶段 | 保护不足、先倒或依赖不可得组件 | 有前排/保护，存在已知破口 | 多层保护且已检验主要针对，不仅名义坦克数量多 |
| growth / 持续成长 | 15 | 观察期限内无后续有效提升 | 产出到不了关键接收者、过晚或无法改善战斗瓶颈 | 已推导资源分配与启动时间，后续能改善输出窗口/关键击杀或必要保护，有明确限制 | 同资源下持续及时改善获胜所需的关键能力，仍有可兑现空间；集中或群体均可，不要求多人获益 |
| access / 成型效率 | 15 | 当前限制下无法形成 | 多件指定稀有依赖，低血/高争抢不容等待 | 有过渡，可在合理资源内尝试，关键件有风险 | 从已知局面容易完成，可替代且不依赖额外好运 |
| economy / 资源效率 | 10 | 净亏且无补偿 | 无效刷新/无用产出、退出损失大或费用未闭合 | 账本与剩余资源用途已核对，功能位有条件性退出路径 | 相同投入及时改变关键采购/成型，功能位留用或退出优于可行替代，剩余收益未双算 |
| matchup / 针对与覆盖 | 10 | 已知对手直接封锁获胜方式 | 严重依赖单类伤害/控场且无解法 | 能对付相关情景，有可识别克制 | 在约定场景中有直接有效解答，付得起调整成本 |
| flexibility / 缺件与转型 | 5 | 缺一件就完全停止 | 只补挂件、丢失成长引擎或转型无法回本 | 有具体来牌分支、增长出口与分回合转型动作 | 早期可接不同有效引擎，后期能依据积累收敛，各路径代价可承担 |
| finish / 淘汰压力 | 5 | 无法取得对局胜利 | 即使赢也常少存活/拖延给对手成长 | 有赢局与保留英雄的合理路径 | 相同资源下能持续干净获胜或明确增强棋手伤害 |

2分/4分用于相邻锚点间有依据的情况；0.5用于解释明确的中间状态。不使用长小数伪装精度。分值依据当前场景：未来成长潜力放growth，不算进damage；新牌产出放economy，同一张牌兑换出的等级不能再次等额当一份资源。机制协同不单设“连线加分”。

高分需要证据，而不只是缺少反例。纯卡文通常只能支持战斗维度的范围。报告分项时说明每个偏离3分的具体原因；来源共用时允许引用同一条证据，但解释各自产生的不同影响。

当前回合评分只看已形成的战斗作用和从此时起的有效资源机会，不能用早期功能牌的累计产出或已投入等级维持后期高分。完整运营路径评价可以记录早期收益及退出代价，但不得再作为当前保留的奖励。未来产能/检索若已无法改变可兑现动作，不能按名义产量给economy高分；高等级功能位的坦度/控制仍按实际贡献进入战斗维度，不统一设为0。

## 先过约束再加权

- `pass`：在列明的约束和条件下可讨论；不是证明实际能抽到。
- `conditional`：关键合法性或核心规则待验证，只能作条件分支。
- `fail`：使用本局已被禁用的英雄、超人口、不存在的牌、错误装备资格、觉醒路径不合法或预算无法闭合；不参与推荐排名。特殊获取绕过禁用须有明确规则，不能默认可行。

资料缺完整获取概率时，可以给已成型快照打分，但成型效率必须诚实反映未知；尚无可用快照/严重缺损时报告分项与范围或“暂不汇总”，不要填0冒充完整评价。

候选预算应同时记录共同资源包与各自支出；预算里没用掉的能量可以让基线投入有效替代，不能固定闲置使其变弱。按 [投资比较](investment.md) 完成具体动作竞争后才评价资源效率；“付得起”不能证明提前觉醒最优，100分量表不能替代抽卡曝光、组件延迟与净收益差的计算。公平有两层：

1. **运营路径对照（主要依据）**：相同起点、商店/掉落信息与资源机会，允许不同升级/追觉醒/转型时机、人数及各自积累出的等级。各回合从可核对的前史推导状态，检验能否及时加速并活着兑现。
2. **同等级快照对照（局部辅助）**：可以设置相同真实等级、觉醒张数与装备，仅解释替换结构或技能差异。这会抹去成长速度优势，不能作为成长型构筑的主要推荐依据；禁止凭空假定某回合全员10/40/100级后倒推出发育可行。

完成体优势不能冒充运营优势。官方发布的全觉醒阵容要保留原版记录，不能静默降配后宣称击败了它。若将其标准化用于实验，写“标准化基线”，同时检验同资源合理强化后的版本。

## 将鲁棒性用于推荐决策

保留8维权重；本次补充更新适用约束与评分依据，不把新增要求伪装成实战校准。禁用已知时，双方按同一可用集合比较；原基线含被禁英雄就标为本局不可用，另建合法基线，不能以非法原版低分证明候选更强。禁用未知时按各相关阵营分别给适用/改路分支，不算无来源的平均分或禁用概率。

**战斗转化与合法运营准入先于加权。** 联合 [成长检查](growth.md) 和 [战斗评估](combat-evaluation.md)，验证资源如何到达接收者、改变属性/技能及有效输出窗口，并推进双方关键减员后的战局。全队总级/增级较慢不是淘汰依据；能在对手追上前形成有依据的获胜/淘汰窗口也可成为完整路线。反之，齐件后仍无法兑现且没有可执行调整出口的方案，不能由高总级、未来成长或易成型分掩盖。缺战斗证据时标为待验证，不等于已证明弱，也不等于默认推荐。过渡出口可以是集中分配、补保护、补副C或更合适的生产引擎，不强制换成总产量更高的引擎。

当前输出/生存只计当前资源在目标和出手条件下能兑现的作用；growth只评观察期限内后续增量能否继续改善这些能力。主C更早击杀带来的敌方减员、己方承伤减少和额外输出时间是同一因果链，解释其影响但不把整条收益分别重复加满多个维度。finish按获胜后的实际存活英雄和扣血规则评，不默认首杀、单核或总DPS更高就有更强淘汰压力。不通过任意提高damage权重或给“集中度”额外加分来修复分析缺口。

- **成型效率（15）：** 看从本局已有牌到有效成长引擎及可战斗状态的支出、品阶门槛、关键张数和等待风险。“容易拼出名单”不能替代“及时启动有竞争力的增长”。缺少每张≥4阶主C、≥3阶构筑牌的换路出口时，不能只凭理想完成体给成型高分。
- **缺件与转型（5）：** 看主C/构筑牌未到、无法觉醒、相关关键件同时缺失时能否按当时来牌换到另一有效引擎，及装备、等级、能量与停产损失；早期允许整队重构，后期按剩余时间收敛。低阶替身数量不代表路线数量。禁用未知时还看被禁后能否改路；已知未被禁的阵营不重复受罚。多个备选共享同一失效依赖，不算独立路线。
- **战力与成长：** 在缺牌分支按实际替代阵容重算；不能沿用完整引擎的产出，再只从转型分里扣一点。新收益不能与已移除组件的收益并存。

合法性与推荐适用性分开：一套牌可以合法却脆弱。没有可执行缺牌路线的方案不得作为默认运营推荐，即使加权总分高，也只能列为关键件齐备后的条件上限。已实际持有核心的局面应按现状评价，不假装再次经历未抽到它的风险；仍需检查尚缺觉醒牌和后续组件。脚本不替agent作这项判断。

至少对相关的关键牌未到/晚到和共同依赖缺失给出明确结果；数值证据不足时用有依据的失败判断，不强凑8维分数。不得统一“每多一个阵营扣X分”，也不通过调权重让想推荐的方案取胜。

每个关键回合分别说明路径选择与结果：继续追原引擎、提前转另一体系、晚期保留成熟资产，各自何时加速/落后。转型后的战力按丢失和保留的实际等级重算，不能无损继承另一前史。无来牌概率时不给整棵决策树算平均分；呈现关键节点分数与不利路径表现即可。同一树的互斥分支不得把收益加总，几条前史汇合也不得抹去等级与资源差。

## 情景与区间

同一个情景中每项给 `low/base/high`，且 `0 ≤ low ≤ base ≤ high ≤ 5`。上下界来自不利/基准/有利的机制解释或条件变动，说明各边界为什么变化；这是情景包络，不是统计置信区间，也不保证所有极端同时实现。

主导胜负的未知规则需要分成显式情景，不能仅用很窄的±1分掩盖。核心默认K/N临时等级与不触发司空震等连锁已确认，正常分配应计入相应英雄的收益；尚未确认的结算时点、取整、临时等级是否跨技能节点等才分情景。不要以这些局部未知为由把已知核心收益归零。输出/生存评分先使用新增成长、技能节点与抗性模型进行有来源的局部校核。

每个情景单独打分。可选情景：基准、核心晚到、关键装备缺失、同卡争抢、面对控制/切后/反普攻等。权重来自已知环境；无环境样本时等权只能叫压力检查，不能解释为真实对手分布。通常不必把所有情景压成一个总分。

成对比较用 `Δbase = S候选 − S基线`。边界可保守计算为 `[S候选low − S基线high, S候选high − S基线low]`，注明未建相关性；若可对齐同一随机条件，优先给同条件差分。重叠不自动等于完全无信息，但不能仅凭点估计宣布稳定领先。

进行有解释的权重敏感性检验，例如生存+5、成长−5，成型+5、输出−5；两者同时改同一套权重。如果翻转，给出适用偏好，不写无条件第一。不要把分数差门槛设成统计显著性。

## 决策措辞

- 机制明确且同资源在相关情景稳定领先：推荐用于该条件，仍说明是否经过实战。
- 有单一指标提升，战斗结果或运营未明：称“值得测试的改良候选”。
- 只有稀有天赋/全觉醒/特定对手时领先：条件分支或上限方案。
- 已证负协同，或者正常情景不如基线：拒绝/修改；不要因原创而加分。

分别给“机制依据：原文/推导/假设”“实战校准：无/样本数及范围”。不以一个0.8置信系数乘总分来掩盖未知。

## 可选算术账本

不写JSON也能评分。需要复核时由 agent 填下述结构，`score.py` 只校验数值/引用存在并汇总，不理解证据，不自动读卡牌生成分数。一个文件对应一个共同情景，方案不自动排序。脚本会排除fail方案；conditional结果明确标注。

战斗转化准入、有效成长、转型合理性与节点前史由agent判断，脚本不会执行这些检查。预算字段可保留在内部算术账本，默认用户报告不展示累计能量/逐笔成本。不同回合/分支用各自情景，不能用一份终局账本替代整条路径研究。

```json
{
  "rubric": "wxq-rubric-1",
  "policy_version": "wxq-policy-4",
  "scenario": {
    "id": "同资源情景标识",
    "stage": "具体R几与决策树节点；状态须由该路径前史推导",
    "budget": "双方相同能量/张数/装备获取条件及支出说明",
    "opponents": "对手假设或诊断场景",
    "assumptions": ["真实等级假设", "影响评分的规则分支"],
    "calibration": "理论分析，无实战样本"
  },
  "evidence": {
    "E1": {"source": "英雄牌/1591/描述", "claim": "本次判断所依据的卡文与具体推导"}
  },
  "baseline": "B0",
  "lineups": [{
    "id": "B0",
    "label": "基线名称",
    "legality": "conditional",
    "constraints": ["人数/张数/装备/能量校验和条件"],
    "dimensions": {
      "damage": {"low": 2, "base": 3, "high": 4, "evidence": ["E1"], "reason": "为什么得到此范围，以及什么会使评价改变"}
    }
  }]
}
```

上面只展示一个维度；实际提交必须包含表中全部8个键。顶层可加 `weights`，需全部8维、有限非负值且合计100。顶层可加 `sensitivity_weights`，形如 `{"保命偏好": {全部8维权重}}`。不要把此节的不完整结构当可执行测试输入。
