# 成长速度、资源分配与战斗兑现

这是构筑的资源分析，与 [战斗转化评估](combat-evaluation.md) 同时进行。用户指出过低阶易成型却成长慢的问题，也观察到集中资源有时能以较低总等级取得战斗优势。应检验资源能否在获胜窗口内兑现，不能先最大化全队等级再补战斗理由，也不能将单核优势泛化。全队总增级用于记录生产规模，各接收者的实际作用决定其价值。

## 找到增长的放大环节

逐个候选解释其链条：**启动资源 → 有效事件 → 放大/重放 → 英雄接收 → 再投入 → 下轮速度变化**。来源可包括棋手、英雄、效果牌、装备和天赋。只接入文本允许的环节，不要求所有体系形成循环。

- 一次动作给谁、几名英雄、各多少等级？比较群体放大、集中主C、补保护/副C门槛的合法路径；关键接收者增加的战斗能力可能比全队总新增更重要。挂件的等级也须检查是否影响关键施法或生存。
- 重放/复制/觉醒如何增加每轮事件数或接收人数？其新增收益是否超过新增人口、购牌、升级和等待成本？
- 产牌/刷新/返利是否能在同回合合法转为更多有效出牌？生成牌不等于使用牌，免费刷新也不等于有钱购买。
- 第一次启动在哪个回合？单张、关键觉醒、完整引擎分别何时开始加速？需提前几回合买下生产者，才在比较时点积累足够等级？
- 随机目标、资源枯竭、次数上限或等级转移怎样限制速度？不用“指数增长”“无限”替代合法性与资源推导。

棋手参与发动机选择，但从零构筑且棋手未锁定时，按 [初始构筑入口与棋手增益匹配](initial-build-player-fit.md) 先建立A类标签基线和缺陷账本，再比较棋手对启动、额外事件、等级放大、复制与供牌的作用及条件。已锁定棋手时，早期换英雄体系也不能改换棋手。某棋手对低阶/特定品阶的奖励只是一个收益项，不能因此排斥能显著加速队伍成长的高阶组件。

## 按回合记录增长，而非凭空指定完成体等级

对决定路线选择的回合分别记录下表；中间回合的资源和增长账仍要闭合。结论随来牌条件给上下界，不编商店概率或“R8必达100级”。

| 观察量 | 核对口径 |
|---|---|
| 启动与加速回合 | 最小发动机可工作、关键觉醒/放大器开始工作、进入稳定生产各是哪一回合；延迟一回合损失什么 |
| 每名英雄真实等级 | 由实际拿牌/合成/事件积累而来；基础合成加级未知时用参数或可证下界，不用自定等级填补 |
| 当轮永久净新增 | 同一事件给所有合法接收者的净增级合计；转移的给出与收到同时记，不能把重新分配当全队新生成 |
| 核心池与临时分配 | 核心总量、接收人数与每人临时份额分开；同一核心既记库存又作为临时战力说明时不重复加进同一个总收益；临时级不跨回合累加为永久级 |
| 队伍分布 | 主C/副C、前排与生产者分别得到多少；达到10/40/100等真实技能节点的人数和时点；不能用只养高一个无关单位抬全队总和 |
| 资源转化瓶颈 | 下笔资源是缩短关键击杀、延长有效输出窗口、补第二伤害源还是加速后续生产；由实际属性/技能与对手条件支持，不按角色固定权重 |
| 后续速度 | 下一轮可持续生产的事件数、等级量、资源消耗；无法支付后续出牌就不能沿用本轮峰值 |
| 转型后的状态 | 上场等级变化、离场/出售丢失的成长、保留下来的资产、停止生产的回合与新体系追平所需时间 |
| 功能位的退出 | 经济/检索需求还剩多少、该单位当前战斗作用、能否合法转移、何时停投与换位；累计等级不等于当前有效战力 |

可手算 `G_perm(r)=Σ_i ΔL_perm,i(r)`，将英雄获得与失去都计入；累计英雄成长按实际留存状态跟踪。每轮新增总级和主C/前排份额一起看。需要研究成长效率时，可对比相同投入的新增等级；零费用的被动收益不除以0制造“无限效率”。静态代码只复核算术，不生成评分或代替链条判断。

对经济/检索功能位，按 [阶段价值与退出](investment.md#42-经济检索功能位的阶段价值与退出) 分开记录历史生产、现存等级和未来可兑现贡献。其累计等级不能继续自动支撑成长/战力高分；但等级仍可能转为有效坦度或控制，也不能因经济需求降低就一律当作无用等级。建队时即检查停止追加与退出路线。

## 增长快不等于应该先购买觉醒

完成体从每轮16增至28，只证明觉醒提高了增长率，不证明此回合的9能量应该付给它。涉及买同名牌、过牌或升阶的回合，按 [投资比较](investment.md) 与先升阶的路径比较：不同门槛回合、有效高阶卡槽、放大组件上场时间、天赋、人口、净留存等级和回本时间。只有在同资源竞争用途下仍有优势，才能把早觉醒写为首选。未比较的“先完成核心觉醒再升本”不得作为通用口诀。

## 两种压力测试都必须做

**关键件已经到手：** 同回合/资源下推导候选与基线的等级分配、启动历史和后续增长，再比较实际战斗转化。总增级较慢但能持续先处理关键目标、维持输出或在被追上前形成淘汰压力时，可成为完整路线；必须验证这一窗口，不能凭“单核”二字通过。既无法及时兑现、未来也追不上且无可执行调整出口时才降为过渡或淘汰；不以易抽或没有高阶依赖掩盖问题。

**关键件未到或晚到：** 比较继续追原引擎、用已到组件重构、保留资产转型三种选择。备选须有可兑现战斗路径和所需增长；仅人数齐但二者皆无的盘只算临时保血。晚到引擎若无法在剩余生存时间内补偿重建和战斗损失，应沿新路线收敛；不强求追回全队总级，只检查能否改善关键战斗指标。

“快”来自同回合、同资源机会的对照，不设无本地依据的统一每回合最低总等级。基线也可早期过渡、先觉醒发动机、自然来牌后转型，不冻结为一张高阶愿望名单。无实测环境样本时报告条件增长轨迹与优势成立条件，不声称已知全环境发育标准。

## 从等级到战斗结论

每个引擎都按 [战斗转化评估](combat-evaluation.md) 检查：增长给谁、跨何种门槛、能否接触目标并出手、双方谁先失去关键单位、其后如何改变输出和保护。当前等级带来的战斗能力放在输出/生存，未来仍可兑现的增量放在成长，不重复计分。若总增级增加但关键战斗指标无改善或更差，不因增长快而优先投资。

主对照允许两条路线因运营不同形成不同真实等级。统一等级快照可用于解释某技能或站位的局部效果，但会抹去成长速度差，不可作为构筑推荐的主要依据。
